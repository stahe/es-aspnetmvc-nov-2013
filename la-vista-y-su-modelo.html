    5. La vista y su modelo

    5.1. Introducción

    Volvamos a la arquitectura de una aplicación ASP.NET MVC:

    En el capítulo anterior, examinamos cómo ASP.NET MVC presenta la información de la solicitud [1] a una acción [2a] en forma de un modelo que puede contener restricciones de validación. Este modelo se pasó como entrada a la acción, y nos referimos a él como el modelo de acción. Ahora nos centraremos en el resultado más común de una acción, el tipo ViewResult [ ], que corresponde a una vista V [3] acompañada de su modelo M [2c]. A este modelo lo llamaremos modelo de vista V, para no confundirlo con el modelo de acción que acabamos de estudiar. Uno es la entrada a la acción, el otro es la salida.

    Comencemos creando un nuevo proyecto [Example-03] [1] dentro de la misma solución, del tipo básico ASP.NET MVC:

    Creemos un controlador llamado [First] [2]. El código generado para este controlador es el siguiente:

    
using System.Web.Mvc;
 
namespace Exemple_03.Controllers
{
  public class FirstController : Controller
  {
    public ActionResult Index()
    {
      return View();
    }
 
  }
}

    • líneas 7–10: se ha creado una acción [Index]. El tipo de retorno del método [Index] es el de la clase [ActionResult], de la que se derivan la mayoría de los posibles resultados de acción;
    • línea 9: el método [View] de la clase [Controller] (línea 5) devuelve un tipo [ViewResult], que deriva de [ActionResult]. Este método admite numerosas sobrecargas. Veremos algunas de ellas. La principal es la siguiente:

    • el primer parámetro es el nombre de la vista. Si se omite, la vista utilizada es aquella que tiene el mismo nombre que la acción que produce el [ViewResult], y se buscará en la carpeta [/Views/{controller}], donde {controller} es el nombre del controlador;
    • el segundo es la plantilla de la vista. Si se omite, la vista no tiene plantilla.

public ActionResult Index()

      return View();
}

    5.3. Uso de un modelo fuertemente tipado para pasar información a la vista

    El método anterior tiene el inconveniente de no permitir la detección de errores antes de la ejecución. Por lo tanto, si la vista [Action01.cshtml] utiliza el código

    
<h4>@ViewBag.Info</h4>

    se producirá un error porque la propiedad [Info] no existe. La creada por la acción [Action01] se llama [info]. Por lo tanto, podemos utilizar un modelo fuertemente tipado para evitar este problema.

    En uno de los ejemplos comentados anteriormente, la acción era la siguiente:

    
    // Action10
    public ContentResult Action10(ActionModel03 modèle)
    {
      string erreurs = getErrorMessagesFor(ModelState);
      string texte = string.Format("email={0}, jour={1}, info1={2}, info2={3}, info3={4}, erreurs={5}",
        modèle.Email, modèle.Jour, modèle.Info1, modèle.Info2, modèle.Info3, erreurs);
      return Content(texte, "text/plain", Encoding.UTF8);
}

    La acción [Action10] pasaba seis datos (Email, Day, Info1, Info2, Info3, errors) a su cliente como una cadena. Pasaremos esta información a un modelo de vista [ViewModel01]. Dado que este modelo utiliza información de [ActionModel03], lo derivaremos de esa clase.

    Empezamos copiando [ActionModel03] del proyecto [Example-02] al proyecto actual [Example-03]:

    y cambiamos su espacio de nombres para que coincida con el del proyecto [Example-03]:

    
using System.ComponentModel.DataAnnotations;
namespace Exemple_03.Models
{
  public class ActionModel03
  {
    [Required(ErrorMessage = "Le paramètre email est requis")]
    [EmailAddress(ErrorMessage = "Le paramètre email n'a pas un format valide")]
    public string Email { get; set; }
 
    [Required(ErrorMessage = "Le paramètre jour est requis")]
    [RegularExpression(@"^\d{1,2}$", ErrorMessage = "Le paramètre jour doit avoir 1 ou 2 chiffres")]
    public string Jour { get; set; }
 
    [Required(ErrorMessage = "Le paramètre info1 est requis")]
    [MaxLength(4, ErrorMessage = "Le paramètre info1 ne peut avoir plus de 4 caractères")]
    public string Info1 { get; set; }
 
    [Required(ErrorMessage = "Le paramètre info2 est requis")]
    [MinLength(2, ErrorMessage = "Le paramètre info2 ne peut avoir moins de 2 caractères")]
    public string Info2 { get; set; }
 
    [Required(ErrorMessage = "Le paramètre info3 est requis")]
    [MinLength(4, ErrorMessage = "Le paramètre info3 doit avoir 4 caractères exactement")]
    [MaxLength(4, ErrorMessage = "Le paramètre info3 doit avoir 4 caractères exactement")]
    public string Info3 { get; set; }
  }
}

    • línea 5: le añadimos la propiedad [Errors].

    Ahora escribimos la acción [Action02] que:

    • toma el modelo de acción [ActionModel03] como entrada;
    • y devuelve el modelo de vista [ViewModel01].

    Su código es el siguiente:

    
    // Action02

    {

    • línea 4: los errores relacionados con el modelo de acción [ActionModel03] se agregan a la cadena [errors]. El método [getErrorMessagesFor] se describió en la página 60 y se incluyó en el controlador [First] del nuevo proyecto;
    • línea 5: se invoca el método [View] con un parámetro. Este es el modelo de vista. La vista en sí no se especifica. Por lo tanto, se utilizará la vista predeterminada [/Views/First/Action02]. El modelo de vista [ViewModel01] se instancia e inicializa con los cinco datos del modelo de acción [ActionModel03] y la información de [errors] construida en la línea 4.

    Las características de la lista desplegable HTML se presentaron en la sección 2.5.2.6. Repasémoslas:

    Combo
    <select size="1" name="cmbValues">
    <option value="1">opción1</option>
    <option selected="selected" value="2">opción 2</option>
    <option value="3">Opción 3</option>
    </select>

    Etiqueta HTML
    <select size=".." name="..">
    <option [selected="selected"] value=”v”>...</option>
    ...
    </select>
    muestra el texto entre las etiquetas <option>...</option> en una lista
    atributos
    name="cmbValeurs": nombre del control.
    size="1": número de elementos visibles de la lista. size="1" hace que la lista sea equivalente a un cuadro combinado.

    public ViewResult Action08Post(ApplicationModel application, FormCollection posted)
    {

    • la acción [Action08Post] procede de la siguiente manera:

    {

      ViewModel08 modèle = new ViewModel08(application);

    • Línea 5: Se instancia el modelo del formulario. Sin embargo, el constructor utilizado asigna la matriz ["2"] a la propiedad [CheckBoxesField];

      if (posted["CheckBoxesField"] == null)
      {
        modèle.CheckBoxesField = new string[] { };
      }
      if (posted["SimpleChoiceListField"] == null)
      {
        modèle.SimpleChoiceListField = "";
      }
      if (posted["MultipleChoiceListField"] == null)

      }
      // form display
      return View("Formulaire", modèle);
