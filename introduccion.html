    1.1. El papel de ASP.NET MVC en una aplicación web

    En primer lugar, situemos ASP.NET MVC en el contexto del desarrollo de una aplicación web. Por lo general, se basará en una arquitectura de varias capas como la siguiente:

    • la capa [Web] es la capa que está en contacto con el usuario de la aplicación web. El usuario interactúa con la aplicación web a través de páginas web mostradas por un navegador. Es en esta capa donde reside ASP.NET MVC, y solo en esta capa;
    • la capa [business] implementa la lógica de negocio de la aplicación, como el cálculo de un salario o una factura. Esta capa utiliza datos del usuario a través de la capa [Web] y del SGBD a través de la capa [DAO];
    • La capa [DAO] (Data Access Objects), la capa [ORM] (Object Relational Mapper) y el conector ADO.NET gestionan el acceso a los datos del SGBD. La capa [ORM] actúa como puente entre los objetos gestionados por la capa [DAO] y las filas y columnas de las tablas de una base de datos relacional. En el mundo .NET se utilizan habitualmente dos ORM: NHibernate (http://sourceforge.net/projects/nhibernate/) y Entity Framework (http://msdn.microsoft.com/en-us/data/ef.aspx);
    • la integración de estas capas se puede lograr utilizando un contenedor de inyección de dependencias como Spring (http://www.springframework.net/);

    1.2. El modelo de desarrollo ASP.NET MVC

    ASP.NET MVC implementa el patrón arquitectónico MVC (Modelo-Vista-Controlador) de la siguiente manera:

    El procesamiento de una solicitud del cliente se lleva a cabo de la siguiente manera:

    1. solicitud: las URL solicitadas tienen el formato http://machine:port/contexte/Controlleur/Action/param1/param2/....?p1=v1&p2=v2&... El [Front Controller] utiliza un archivo de configuración para «enrutar» la solicitud al controlador correcto y a la acción correcta dentro de ese controlador. Para ello, utiliza la ruta [Controller/Action] de la URL. El resto de la URL [/param1/param2/...] consta de parámetros opcionales que se pasarán a la acción. La «C» de MVC se refiere aquí a la cadena [Front Controller, Controller, Action]. Si la ruta [Controller/Action] no conduce a un controlador o acción existentes, el servidor web responderá que no se ha encontrado la URL solicitada.
    2. Procesamiento
    • La acción seleccionada puede utilizar los parámetros que le ha pasado el [controlador frontal]. Estos pueden provenir de varias fuentes:
    • la ruta [/param1/param2/...] de la URL,
    • los parámetros [p1=v1&p2=v2] de la URL,
    • los parámetros enviados por el navegador con su solicitud;
    • al procesar la solicitud del usuario, la acción puede necesitar la capa [business] [2b]. Una vez procesada la solicitud del cliente, puede desencadenar diversas respuestas. Un ejemplo clásico es:
    • una página de error si la solicitud no se ha podido procesar correctamente
    • una página de confirmación en caso contrario
    • la acción indica que se muestre una vista específica [3]. Esta vista mostrará datos conocidos como el modelo de vista. Esta es la M de MVC. La acción creará este modelo M [2c] e indicará que se muestre una vista V [3];
    1. respuesta: la vista V seleccionada utiliza el modelo M construido por la acción para inicializar las partes dinámicas de la respuesta HTML que debe enviar al cliente y, a continuación, envía esta respuesta.

    Ahora, aclaremos la relación entre la arquitectura web MVC y la arquitectura por capas. Dependiendo de cómo definamos el modelo, estos dos conceptos pueden estar relacionados o no. Consideremos una aplicación web ASP.NET MVC de una sola capa:

    Si implementamos la capa [Web] con ASP.NET MVC, tendremos efectivamente una arquitectura web MVC, pero no una arquitectura multicapa. En este caso, la capa [Web] se encargará de todo: presentación, lógica de negocio y acceso a datos. Son las acciones las que realizarán este trabajo.

    Ahora, consideremos una arquitectura web multicapa:

    La capa [Web] se puede implementar sin un marco de trabajo y sin seguir el modelo MVC. Entonces tendremos una arquitectura multicapa, pero la capa Web no implementa el modelo MVC.

    Por lo tanto, la capa [Web] superior se puede implementar con ASP.NET MVC, lo que da como resultado una arquitectura por capas con una capa [Web] de estilo MVC. Una vez hecho esto, podemos sustituir esta capa de ASP.NET MVC por una capa clásica de ASP.NET (WebForms) sin modificar el resto (lógica de negocio, DAO, ORM). De este modo, obtenemos una arquitectura en capas con una capa [Web] que ya no se basa en MVC.

    En MVC, dijimos que el modelo M era el de la vista V, es decir, el conjunto de datos mostrados por la vista V. Se ofrece otra definición del modelo M en MVC:

    Muchos autores consideran que lo que se encuentra a la derecha de la capa [Web] constituye el modelo M de MVC. Para evitar ambigüedades, podemos referirnos a:

    • el modelo de dominio cuando nos referimos a todo lo que se encuentra a la derecha de la capa [Web]
    • el modelo de vista cuando nos refiramos a los datos mostrados por una vista V

    En lo sucesivo, el término «modelo M» se referirá exclusivamente al modelo de una vista V.
