    7. Ajaxificación de una aplicación ASP.NET

    7.1. El papel de AJAX en una aplicación Web

    For now, the learning examples we’ve studied have the following architecture:

    Para pasar de una vista [Vista1] a una vista [Vista2], el navegador:

    • envía una petición a la aplicación web;
    • recibe la vista [Vista2] y la muestra en lugar de la vista [Vista1].

    Este es el patrón clásico:

    • del navegador;
    • el servidor web genera una vista en respuesta al cliente;
    • visualización de esta nueva vista por el navegador.

    Existe otro modo de interacción entre el navegador y el servidor web: AJAX (JavaScript y XML asíncronos). Esto implica interacciones entre la vista mostrada por el navegador y el servidor web. El navegador sigue haciendo lo que mejor sabe hacer -mostrar una vista HTML- pero ahora está controlado por JavaScript incrustados dentro de la vista HTML mostrada. El proceso es el siguiente:

    • en [1], se produce un evento en la página mostrada en el navegador (clic en un botón, cambio de texto, etc.). Este evento es interceptado por JavaScript (JS) incrustado en la página;
    • en [2], el código JavaScript realiza una petición HTTP tal y como habría hecho el navegador. La petición es asíncrono: el usuario puede seguir interactuando con la página sin ser bloqueado mientras espera la respuesta HTTP. La petición sigue el flujo de procesamiento estándar. Nada (o muy poco) la distingue de una petición estándar;
    • En [3], se envía una respuesta al cliente JavaScript. En lugar de una vista HTML completa, lo que se suele enviar es una vista HTML parcial, una alimentación XML o JSON (JavaScript Object Notation);
    • En [4], JavaScript recupera esta respuesta y la utiliza para actualizar una región de la página HTML mostrada.

    For the user, there is a change in the view because what they see has changed. However, there is no full page reload; instead, only a partial modification of the displayed page occurs. This helps make the page more fluid and interactive: because there is no full page reload, we can handle events that previously could not be managed. For example, offering the user a list of options as they type characters into an input field. With each new character typed, an AJAX request is sent to the server, which then returns additional suggestions. Without AJAX, this kind of input assistance was previously impossible. We couldn’t reload a new page with every character typed.

    7.3.3. La acción [Action01Post]

    La acción [Action01Post] que gestiona la petición Ajax HTTP es la siguiente:

    
    [HttpPost]
    public PartialViewResult Action01Post(FormCollection postedData, SessionModel session)
    {
      // simulation wait
      Thread.Sleep(2000);
      // instantiate the action model
      ViewModel01 model = new ViewModel01();
      // calculation time
      model.CalculationTime = DateTime.Now.ToString("hh:mm:ss");
      // Update the model
      TryUpdateModel(model, postedData);
      if (!ModelState.IsValid)
      {
        // return an error
        model.Error = getErrorMessagesFor(ModelState);
        return PartialView("Action01Error", model);
      }
      // Every other time, we simulate an error
      int val = session.Randomizer.Next(2);
      if (val == 0)
      {
        model.Error = "[random error]";
        return PartialView("Action01Error", model);
      }
      // calculations
      model.AplusB = string.Format("{0}", model.A + model.B);
      model.AminusB = string.Format("{0}", model.A - model.B);
      model.AMultipliedByB = string.Format("{0}", model.A * model.B);
      template.A/B = string.Format("{0}", template.A / template.B);
      // view
      return PartialView("Action01Success", template);
}

    • el código incrustado en el navegador [2] requiere conocimientos de JavaScript, HTML y CSS, pero es agnóstico a la tecnología del servidor web [1].

    Así, esta arquitectura facilita el trabajo en paralelo de equipos con diferentes conjuntos de habilidades. Es especialmente adecuada para aplicaciones de una sola página.
