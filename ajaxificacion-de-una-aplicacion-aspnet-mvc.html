    7. Ajaxificación de una aplicación ASP.NET MVC

    7.1. El papel de AJAX en una aplicación web

    Por ahora, los ejemplos de aprendizaje que hemos estudiado tienen la siguiente arquitectura:

    Para pasar de una vista [View1] a otra [View2], el navegador:

    • envía una solicitud a la aplicación web;
    • recibe la vista [View2] y la muestra en lugar de la vista [View1].

    Este es el patrón clásico:

    • solicitud del navegador;
    • el servidor web genera una vista en respuesta al cliente;
    • el navegador muestra esta nueva vista.

    Existe otro modo de interacción entre el navegador y el servidor web: AJAX (JavaScript asíncrono y XML). Esto implica interacciones entre la vista mostrada por el navegador y el servidor web. El navegador sigue haciendo lo que mejor sabe hacer —mostrar una vista HTML—, pero ahora está controlado por JavaScript incrustado en la vista HTML mostrada. El proceso es el siguiente:

    • en [1], se produce un evento en la página mostrada en el navegador (clic en un botón, cambio en el texto, etc.). Este evento es interceptado por el JavaScript (JS) incrustado en la página;
    • en [2], el código JavaScript realiza una solicitud HTTP tal y como lo habría hecho el navegador. La solicitud es asíncrona: el usuario puede seguir interactuando con la página sin verse bloqueado mientras espera la respuesta HTTP. La solicitud sigue el flujo de procesamiento estándar. Nada (o muy poco) la distingue de una solicitud estándar;
    • En [3], se envía una respuesta al cliente JavaScript. En lugar de una vista HTML completa, lo que se envía suele ser una vista HTML parcial, un feed XML o JSON (JavaScript Object Notation);
    • En [4], JavaScript recupera esta respuesta y la utiliza para actualizar una región de la página HTML mostrada.

    Para el usuario, se produce un cambio en la vista porque lo que ve ha cambiado. Sin embargo, no se recarga la página completa; en su lugar, solo se produce una modificación parcial de la página mostrada. Esto contribuye a que la página sea más fluida e interactiva: al no recargarse la página completa, podemos gestionar eventos que antes no se podían manejar. Por ejemplo, ofrecer al usuario una lista de opciones a medida que escribe caracteres en un campo de entrada. Con cada nuevo carácter escrito, se envía una solicitud AJAX al servidor, que a continuación devuelve sugerencias adicionales. Sin AJAX, este tipo de asistencia en la entrada era imposible anteriormente. No podíamos recargar una nueva página con cada carácter escrito.

    7.3.3. La acción [Action01Post]

    La acción [Action01Post] que gestiona la solicitud HTTP de Ajax es la siguiente:

    
    [HttpPost]
    public PartialViewResult Action01Post(FormCollection postedData, SessionModel session)
    {
      // wait simulation
      Thread.Sleep(2000);
      // action model instantiation
      ViewModel01 modèle = new ViewModel01();
      // calculation time
      modèle.HeureCalcul = DateTime.Now.ToString("hh:mm:ss");
      // model update
      TryUpdateModel(modèle, postedData);
      if (!ModelState.IsValid)
      {
        // returns an error
        modèle.Erreur = getErrorMessagesFor(ModelState);
        return PartialView("Action01Error", modèle);
      }
      // every other time, an error is simulated
      int val = session.Randomizer.Next(2);
      if (val == 0)
      {
        modèle.Erreur = "[erreur aléatoire]";
        return PartialView("Action01Error", modèle);
      }
      // calculations
      modèle.AplusB = string.Format("{0}", modèle.A + modèle.B);
      modèle.AmoinsB = string.Format("{0}", modèle.A - modèle.B);
      modèle.AmultipliéparB = string.Format("{0}", modèle.A * modèle.B);
      modèle.AdiviséparB = string.Format("{0}", modèle.A / modèle.B);
      // view
      return PartialView("Action01Success", modèle);
}
